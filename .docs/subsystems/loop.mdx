# The Loop

`sirius run --workers N --agent-cmd "<cmd>" [--review-cmd "<cmd>"]` drives the fleet. One iteration is up to ten phases, and `run_iteration` is deterministic and fully mockable — the loop's correctness properties are tested through it without a live `amt`, `hayven`, or agent.

```
claim → map → lock → brief → work → gate → [review ⇄ fix] → receipt → release
```

Those ten strings are the `PHASES` constant (`review` and `fix` appear only when the review stage is on) and appear verbatim in the NDJSON `phase` field. `sirius run --json` streams one JSON object per line to stdout (each event is a single atomic `write_all`, so parallel workers never interleave a line).

## Parallel workers in isolated worktrees

`cmd_run` spawns each worker as a real OS thread (`worker_loop` in `src/main.rs`) — the old v1 loop ran them sequentially, so `--workers 3` gave three roster names and zero parallelism. With no `--workers` flag a launch runs **one** worker; an explicit `--workers N` always wins (`0` is raised to 1) — `worker_concurrency` neither defaults nor caps it any more (`resolve_workers`; the `fleet start` event carries `workers` / `workers_source` / `workers_why`). Each worker gets:

- its **own git worktree** at `.sirius/worktrees/<worker>` (created from the launch base commit, removed at exit). Agents, git diffs, and gate test runs all execute inside it — parallel agents in one shared checkout would cross-contaminate every baseline diff and race on git's `index.lock`. If a worktree cannot be created the launch **fails** (exit 1); there is deliberately no fallback to the shared checkout. A worktree left behind by a killed run is never just deleted at launch (`clear_stale_worktree`): its uncommitted or ref-less work is committed and pinned first — at `refs/sirius/wip/<issue>` when the worker's unfinished ledger iteration names the issue (`Ledger::unfinished_issue`), `refs/sirius/wip-failed/<issue>` if it was caught mid-merge, else `refs/sirius/wip-orphaned/<worker>/<sha12>` — and a tree whose work could not be (fully) preserved is moved aside to `<name>.stale-<ts>` instead of removed.
- **worktree setup** (SIRF-50): a fresh worktree has tracked files only (no `node_modules`, no `.venv`), so `worktree.setup_cmd` — or one detected from the base tree's lockfile; `""` disables it — runs in each worktree serially before any agent starts, under `worktree.setup_timeout_secs` (default 1800s), logged to `.sirius/logs/setup-<worker>.log`. A worker whose setup fails does not start (a `fleet` / `setup_failed` event; the run exits 1); if every worker fails the fleet refuses to launch. Each iteration re-runs setup (keeping the issue lease alive) only when its base changed a lockfile since the last install (`gate::setup_is_stale` against the stamp `write_setup_stamp` left).
- its **own ledger connection** (WAL + a 5s busy timeout serialize concurrent writers) and its own `amt`/`hayven` adapters, which run against the repo, not the worktree.
- a **fresh base per iteration** (SIRF-42): `iteration_base` resolves the fleet's base ref (`review.base_ref`, else the branch launched from) to its tip *at claim time*, falling back to the launch base when there is no base ref or it does not resolve — in a serial blocker chain each ticket sees its merged predecessors. That sha is the claim event's `base_sha`, the worktree reset target, `SIRIUS_BASE`, the gate baseline, and the start of every review diff range.
- a per-issue branch, stamped at COMPLETION: each iteration hard-resets the worktree to its iteration base and works **detached** (a parked branch would block a sibling worktree from re-claiming the same issue); on a completed iteration sirius auto-commits any uncommitted agent work and points `sirius/<issue>` at the result — so completed work survives after the worktree is torn down (non-committing agents included), and one iteration's leftovers can never poison the next issue's gate. If stamping fails, the issue is NOT advanced (the work is pinned for resume instead — see below). Every worktree path handed to git goes through `gitrange::git_path`, which strips Windows' `\\?\` verbatim prefix.

Because the code-graph daemon watches the MAIN checkout and cannot see worker worktrees, fleet iterations never trust `affected-tests` selections — the gate always takes the doubt path (full suite under the default fallback). Narrow selection remains for the serial `sirius gate` CLI. Worktrees are created serially by `cmd_run` before any thread spawns (concurrent `git worktree add/prune` race on `.git` locks), and a `.sirius/run.pid` guard refuses a second fleet in the same repo — a second `sirius run` would otherwise force-remove the first fleet's live worktrees.

Workers share an atomic iteration budget (`--max-iterations`, refunded for idle NoWork probes so the cap counts real iterations) and a failure flag (exit code 1 if any worker trips its 5-consecutive-error budget). A worker whose `NoWork` answer carries `retry_after` (issues exist but are leased) waits briefly — capped at 30s, three probes — before giving up, so the pool doesn't drain while siblings may still release work back to the board. A REFUSED lease refresh at the pre-spawn check (amt answers `claimed:false` — the lease lapsed) aborts the iteration before the agent spawns, instead of putting two agents on one issue. `sirius run` also **refuses to start** (exit 1) when `gate.test_cmd` is unset or blank (unless `gate.fallback` is `pass-with-warning`): every gate would fail closed, burning a full agent run per issue while advancing nothing. It likewise refuses (exit 2) when `--agent-cmd`'s program is not on `PATH` — `shell::agent_program` reads the first word past any `NAME=value` assignments and `exec`/`command`/`nohup`, and `shell::find_program` looks it up (trying `PATHEXT` extensions on Windows, so `claude.cmd` counts). A command too dynamic to read statically (a variable, a subshell, a builtin, a relative path, …) skips the check rather than risk a false refusal.

## The agent contract

Every agent and reviewer process gets `SIRIUS_ISSUE`, `SIRIUS_WORKER`, `SIRIUS_WORKTREE`, `SIRIUS_BASE` (the iteration base), `SIRIUS_BASE_REF` (when the fleet tracks a branch), `SIRIUS_PHASE` (`work` | `review` | `fix`), `AMT_AGENT=sirius/<tree>`, and `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` in its environment — plus `SIRIUS_RESUMED_FROM` / `SIRIUS_RESUME_REF` when earlier work was merged back in, `SIRIUS_PRIOR_WORK` when judged-and-failed earlier work exists, and (work/fix, on a retry) `SIRIUS_LAST_GATE_TAIL`, the previous attempt's failing gate output; and `{issue}` / `{worker}` are filled in in `--agent-cmd` / `--review-cmd` (`template_cmd`). The worker's `--agent-cmd` runs through the same explicitly resolved shell as `gate.test_cmd` (`shell::resolve_shell`: `SIRIUS_SHELL`, else `/bin/sh -c` on unix, else on Windows a POSIX `sh` on `PATH` or `%ComSpec% /C` — see [subsystems/gate](./gate)), never the shell that launched Sirius; review spawns stay on literal `sh -c`, since their wrapper script is Sirius-built POSIX. `AMT_AGENT` — plus `--author sirius/<tree>` on every comment and decision Sirius itself writes — attributes fleet work on the board to the worker, not to the human running the fleet. The gate no longer moves the issue status itself: the release step does, once, after any review.

The WORK⇄GATE loop is a reusable closure (`run_work_gate`) returning `WorkGate::Done { work_ok, gate_result, exit, log, timed_out, env_fault }` or `WorkGate::Exit(outcome)` for terminal paths that already did their bookkeeping (lease lost, a WORK agent killed by the timeout). Review fix rounds reuse it with `SIRIUS_PHASE=fix`, so they get the same heartbeat, timeout, log capture, baseline diff, and retry budget. When the agent fails, the release comment names it ("agent exited 1 (see .sirius/logs/…)") rather than blaming the gate. A failing gate's comment leads with the failing output's tail, and the `gate` event carries it as `error_tail`. When the gate output looks like a missing dependency (an environment fault, SIRF-50), the worktree setup is re-run and the gate re-evaluated — at most once per WORK⇄GATE unit, after a checked lease renewal, without consuming a work attempt (`env_fault` / `setup_rerun` on the `gate` event); `env_fault` on `Done` means the final failure still looked like the environment's and setup could not repair it (no setup command, or the re-run failed). See [subsystems/gate](./gate).

## Agent timeouts: idle watchdog, hard cap, finish grace (SIRF-41)

WORK and FIX agents run under `Runner::run_agent_watched` with two limits from `Config::agent_timeouts(labels)`: an **idle** window (`timeouts.idle_secs`, default 1800s) and a **hard** cap (`timeouts.hard_secs`, default 10800s; a legacy `agent_timeout_secs` other than the old 1800 default still sets the hard cap), each overridable per ticket by the first `timeouts.routes` entry whose labels match. The agent is killed only when it shows no progress for the idle window — progress is its log growing or `shell::worktree_probe` (HEAD plus a hash of `git status --porcelain -uall` and every listed path's size+mtime, run with `--no-optional-locks`) returning a different snapshot, probed every `idle/3` clamped to 1–30s and once more right before any kill — or when the hard cap runs out. A kill due within `FINISH_GRACE_SECS` (60s) of a HEAD move is deferred once by that long: an agent that just committed is finishing, not stuck. A kill takes the whole process tree. The `work`/`fix` event and the `agent_timeout` release event carry `timeout_kind` (`idle` | `hard`), and the release comment names the limit that fired. Reviewer, integration, and canary runs keep the plain wall clock.

Headless `claude -p` kills its own background helper tasks after `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` (600s by default), often still exiting 0. Sirius exports `0` (wait indefinitely — Sirius owns the timeout) to every agent and reviewer, and an agent log whose last three non-blank lines carry the CLI's "Background tasks still running … terminating" message is treated as a failed run whatever the exit code (`shell::bg_tasks_killed_in`; the event gets `reason: agent_bg_tasks_killed`).

## Never lose work: preserve, resume, guard (SIRF-41 / SIRF-49)

Every non-advancing exit pins the worktree's work **before** the issue is released — another worker may claim it the instant it is back in `todo`, and this worker's next reset would wipe the tree. Every mid-iteration release back to `todo` (entity overlap / backoff / claim error, agent timeout, usage-limit pause) goes through `release_back`, which calls `preserve_wip` first, and the final release preserves anything neither advanced nor held; the lease-lost unwind (which does not release the issue) preserves too. `preserve_wip` is a no-op when the tree is clean and HEAD's content is still at the iteration's floor (the base plus anything resumed); otherwise it commits everything (`add -A`, repo hooks skipped, retried under a sirius identity with signing off and a stale `index.lock` cleared) and pins the result with a compare-and-swap (`pin_ref` — an older value the new sha does not contain is parked at `refs/sirius/wip-superseded/<issue>/<sha12>` first). The release comment and the release event's `wip_ref` (`{ref, sha, diffstat[, partial]}`, or `wip_error`) say where it went.

Where it is pinned depends on how the iteration ended:

- **Interrupted** — agent failure or timeout, a usage-limit pause, a lost lease, an entity-claim release, a stamp that failed: `refs/sirius/wip/<issue>`, merged back automatically on the next claim. An agent that itself failed counts as interrupted whatever the gate then said, and so does a gate failure that still looks like an environment fault setup could not repair.
- **Judged** — a gate deadend (agent succeeded, gate failed) or a review `release`: `refs/sirius/wip-failed/<issue>`, never merged back; the next agent is pointed at it (`SIRIUS_PRIOR_WORK`). Resumed work that was part of what got judged moves there with it. A tree caught mid-merge is snapshotted single-parent and always lands here.
- A fix round that does not hold parks its discarded attempt at `refs/sirius/wip-superseded/<issue>/<sha12>` (`park_attempt`) before reverting to the last reviewed checkpoint.

On claim, `resume_work` merges the issue's held (SIRF-32) and preserved work onto the fresh base as real merges — the held commit first, then the wip on top (or only the wip, when it already contains the held commit) — and sets `SIRIUS_RESUMED_FROM` (the last sha merged) and `SIRIUS_RESUME_REF`. Work already on the base drops its ref; work that no longer merges is parked at `refs/sirius/held-conflicted/<issue>` / `refs/sirius/wip-conflicted/<issue>` and the issue starts fresh. Resumed refs are removed (compare-and-delete) only once the resumed work is stamped at completion (`retire_resumed`), so an iteration that ends early resumes again next time; prior failed work the completed work does not contain is parked then.

**Branch guard** (`guard_branch`): after every work/fix agent run in a fleet worktree, an agent that left a named branch checked out has its commit pinned at `refs/sirius/keep/<issue>/<branch>` (suffixed `-<sha12>` rather than overwrite an unrelated earlier pin) and HEAD detached in place with plumbing; the branch itself is never touched. An unborn branch is detached at the iteration's floor. An NDJSON `{"event":"branch_guard", …}` line reports it.

## Models and the usage-limit pause (SIRF-26)

`cmd_run` resolves the fleet's models once (`models::resolve`: `--model` > `models.default` > `$SIRIUS_PARENT_MODEL`; `--review-model` > `models.review` > the worker model) and **refuses to launch** (exit 2) with no worker model unless `--allow-default-model` — naming the model every Claude worker would otherwise silently inherit from `.claude/settings*.json` (`check_models`). It emits a `fleet start` NDJSON event with the resolved models. Per iteration, the claimed issue's Ametrite `labels` pick the worker model (`models::model_for`: first matching `models.routes` entry; fix rounds of un-routed tickets use `models.fix_floor`), and it is injected as `ANTHROPIC_MODEL` + `SIRIUS_MODEL` (reviewer: `ANTHROPIC_MODEL` + `SIRIUS_REVIEW_MODEL`) and the `{model}` placeholder; claim events carry `model` / `review_model`.

All workers share `Fleet.pause` and `Fleet.fallback`. When a FAILED agent or reviewer's last output lines carry a fleet stop (`models::fleet_stop`: a usage/plan limit, a model this CLI version cannot run, or a logged-out CLI), `on_usage_limit` decides by the tier the agent RAN on: a limit/unsupported-model hit on the primary tier with a `models.fallback` configured switches the WHOLE fleet to the fallback tier (announced once: NDJSON `{"event":"fleet","phase":"fallback"}`, spine `fleet.fallback`) and retries the failed phase **in place** on it (work/fix: the WORK⇄GATE loop continues without consuming an attempt; review: a `fell_back` review event + ledger row, then the same try again). Models are re-resolved per spawn from `models::active`. A hit on the fallback tier, with no fallback, or a logged-out CLI pauses the fleet: a work-phase hit returns the issue to `todo` un-advanced (`usage_paused`: no deadend, `fleet.paused` + `job.blocked`; any partial work is pinned at `refs/sirius/wip/<issue>` and resumed on the next claim), a fix-round hit parks its attempt, reverts to the last reviewed checkpoint and escalates, a reviewer hit is not retried; every worker re-checks the pause before each claim and each spawn. `sirius run` then exits **4** after a `{"event":"fleet","phase":"paused"}` event. Agent logs live under the fleet's absolute `.sirius/logs`.

## Review ⇄ fix (SIRF-23)

With `review.cmd` set (or `--review-cmd`), work that passes the gate in a fleet worktree goes through `run_review_stage` (the pure contracts live in `src/review.rs`):

1. **Checkpoint** the worker's uncommitted work, so the reviewer sees exactly `base..HEAD` (`ReviewCtx::base` is the iteration base, never the launch snapshot) and a tampering reviewer can be undone with one `reset --hard`.
2. **Renew both leases** (`renew_checked`) — a refused amt lease aborts the iteration via the shared `lease_lost` unwind, without releasing an issue that is no longer ours.
3. **Review** in a fresh `sh -c 'cd "$SIRIUS_REVIEW_DIR" || exit 1; <cmd>'` process with stdin closed (agents are non-interactive). The findings are the reviewer's final message (`review::findings_json_in` over its captured log) or `$SIRIUS_REVIEW_OUT` if it could write one — so a reviewer needs only read tools. `$SIRIUS_REVIEW_DIR` is ALWAYS a throwaway detached worktree (`add_review_tree`, `.sirius/worktrees/<tree>-review`), never the worker's tree, so the reviewer's hooks and test runs land somewhere deleted afterwards (SIRF-29). With `review.against = current-base-merge` (default) it holds the checkpoint merged onto the current tip of `base_ref`; with `launch-base` (or an unmoved base), the checkpoint itself; with `frontier` (SIRF-30), the checkpoint merged onto the integration frontier built by `frontier::prepare` — the base tip plus the oldest 12 sibling `sirius/*` branches awaiting integration (`frontier::siblings` over one `amt issue list` — `frontier::awaiting`), with `$SIRIUS_DIFF_RANGE = <frontier>..HEAD` and the siblings rendered into `$SIRIUS_SIBLINGS`. Conflicts are attributed by probing (`frontier::probe`): a conflict with the bare base is the base's; otherwise each sibling that conflicts with the work on its own becomes a `sibling-conflict` finding and is dropped from the retried merge. A conflict with the base skips the reviewer and becomes `conflict` findings that block regardless of `block_on`. Throwaway merges run no repo hooks and no rerere (`frontier::THROWAWAY_MERGE_CONFIG`). `review.sequences` (SIRF-31, `frontier::sequence_collisions`) adds `AUTO-` `conflict` findings for migration-style slots this branch takes out of order or shares with a sibling — including this fleet's peers under review right now (`Fleet::inflight`, `register_inflight` / `peers_before`: the peer that reached review first owns the slot; cleared by an `InflightGuard` when the iteration ends, panics included). Entries compare by name and content (`frontier::Entry`). `AUTO-` findings are recomputed every round; reviewer restatements or verdicts on them are dropped (`review::is_auto`), a vanished one counts as fixed (never an accepted rebuttal), and a round whose discovery was incomplete (`facts_complete = false`) keeps the previous round's `AUTO-` findings open. All `git worktree add/remove` go through a process-wide mutex (`worktree_admin`).
4. **Enforce read-only**: `tree_fingerprint` (HEAD + porcelain status + diff of the worker's tree, excluding suite-owned `.suite/` `.hayven/` `.ametrite/` `.sirius/`) before/after; a change is reverted and the round is `tampered`. Missing/malformed JSON, a timeout, or tampering is a review error: retried once, then `on_review_error`.
5. **Fix**: on confirmed blocking findings with rounds left, run the worker in fix mode, then re-gate; the next review sees each finding next to the worker's `fixed`/`rebutted` response. A fix agent failure or timeout, or a gate it cannot repair within `retry_budget`, parks the discarded attempt (`park_attempt`), reverts to the last reviewed checkpoint and escalates — gate-passing work is never traded for a broken fix.
6. **Escalate** on exhaustion or error: `advance-flagged` (advance, label `review:open`, comment the open findings) or `release` (back to `todo`, ledger outcome `deadend`).

**Escapes and canaries** (SIRF-35, `src/escape.rs`, `src/canary.rs`). `sirius escape` records a defect that got past review in the ledger's `escapes` table, against the issue that shipped it (a board comment there; a nudge once a kind escapes twice). Every review prompt gets `$SIRIUS_ESCAPES` — the live (not automated) kinds, most frequent first (`escape::patterns_section`); `--automated-by` retires a kind (`escape_kinds_automated`). `sirius review-canary` replays each escape's fix REVERTED onto the current base, plus `.sirius/canaries/*.patch`, through `review.cmd` with the same env/prompt contract as a round (and `review::read_review_output`, the same findings reader), in a throwaway worktree on a parentless snapshot of the base; a blocking finding on a non-test file the canary changed is a catch, a canary that no longer applies is `stale`, a reviewer error counts as a miss, and a benign control measures false positives. Canaries are blind (issue key `CANARY-<n>`, no escape sharing the canary's kind or fix in the prompt, prompt/output/log deleted after scoring, dead runs swept). Results land in `canary_runs`.

**`sirius integrate`** (SIRF-32, `src/integrate.rs`) builds the same frontier with `frontier::build` (every sibling, not the review cap) in `.sirius/worktrees/integrate` under an atomic pidfile lock (`.sirius/integrate.lock`, hard-linked into place), points `refs/sirius/frontier` at it, and runs `integration.cmd` there (a timeout kills the command's whole process tree — `shell::kill_descendants`). Red records `integration_red` in the ledger meta first, then files one issue per red streak. Only a pass over a complete discovery clears it (left-out, textually conflicting siblings do not block); a run with no command never does; `--clear-red` is the explicit human override. With `integration.on_fail = block` (`integrate::block_reason`, fail-closed), `cmd_run` refuses to launch (exit 3), `worker_loop` pauses the fleet before each claim, and `run_iteration` HOLDS gated work — also when red arrives DURING the review (`ReviewStage::Held` on an integration-red pause, and a re-check after the stage): no review, no receipt, branch preserved and the commit kept at `refs/sirius/held/<issue>`, released to `todo` with outcome `released`; on re-claim `resume_work` (via `resume_held`) merges it back in (`SIRIUS_RESUMED_FROM`, `SIRIUS_RESUME_REF`) and the ref is removed only once the resumed work is stamped (resumed held work that is then judged and failed moves to `wip-failed` instead) — an iteration that ends early resumes again next time.

Every round writes a `review_rounds` ledger row, an NDJSON `review` event, an issue comment, and `review.*` spine events; the receipt's decision title carries the summary (`ReviewSummary::line`). A diff that is empty or touches only `skip_paths` skips the stage.

## Claim order is law

**Ametrite issue first, Hayvenhurst entities second; release in reverse.**

On a hard entity overlap (409), the issue is released back with a comment naming the blocker. Sirius never holds an issue while spinning on a code lock — that is the rule that keeps a stuck worker from parking work nobody else can take.

`lock_entities` walks the entity list in order, accumulating `acquired` claim ids. On any failure it returns without releasing anything; the caller unwinds. `LockResult` carries four shapes: `Locked { claim_ids, verdicts }`, `Overlap { blocker, acquired }`, `OracleBackoff { detail, acquired }`, and `Failed { detail, acquired }` — the last is an *operational* claim failure (daemon unreachable, wrong project, crashed CLI) that surfaces as `IterationOutcome::Error` so the run loop's error budget applies, instead of masquerading as contention and retrying forever.

The `verdicts` vector is parallel to `claim_ids` and records how each claim was actually obtained — `"registered"` (clean) or `"forced"` (oracle-conflicted, then forced under `Oracle202::ForceWithBudget`). It is written to the ledger verbatim rather than fabricating a uniform `"registered"` vector.

## Two failure modes that used to be silent

Both were fixed and both are worth knowing, because the naive version of each looks like it works:

**A `Registered` verdict with no claim id is treated as a claim failure.** The daemon can register a claim and hand back nothing releasable. Pushing the entity *name* as a stand-in id — the old behavior — makes the later `hayven release` silently fail and leaks the lease. Sirius now unwinds instead: it never manages a lease it cannot release.

**Releases are retried and logged.** `release_entity_checked` and `release_issue_checked` both retry with exponential backoff, and on final failure shout to stderr **and** write a `release_failure` policy event. The earlier `let _ = amt.release(...)` swallowed failures, leaving an issue silently locked to a dead worker. A leaked lock is never silent now.

## Adaptive claiming

`claim_decision` picks between `PreClaim` and `RelyOnGate`:

| `claim_mode` | Behavior |
|---|---|
| `always` | always pre-claim entities before work |
| `never` | never pre-claim; rely on the gate to catch collisions |
| `adaptive` *(default)* | read contention from ledger history |

Adaptive counts recent `backoff_409` policy events: **2 or more** within the last **20** sampled events flips it to `PreClaim` (`ADAPTIVE_409_THRESHOLD`, `ADAPTIVE_WINDOW`). Contention is sensed from what actually happened, not configured up front.

## Iteration outcomes

`IterationOutcome` is one of `NoWork { retry_after }`, `Completed`, `ReleasedOverlap`, `Deadend` (gate failed for good — retry budget exhausted, or a structurally-unpassable gate such as an unconfigured `test_cmd` that skips retries entirely; or a review escalated with `release`; or a WORK agent killed by the timeout; deadend note filed), `Error(String)`, or `Paused(String)` (a fleet-wide stop: the issue went back to `todo` un-advanced and the worker stops claiming). Each pass writes exactly one `iterations` row.

## Two output streams, deliberately separate

- **NDJSON on stdout** — iteration phases, for whoever is watching the run.
- **The suite spine** (`.suite/`) — past-tense `job.*` / `gate.*` / `review.*` / `receipt.*` facts for other tools.

They have different vocabularies on purpose, so they never collide. The spine is optional (`None` disables it, as in tests) and best-effort. See [subsystems/suite-spine](./suite-spine).

## Reading the amt claim shape

`amt claim` does not return `{claimed: bool}` on success — it returns the full issue object. `issue_id` keys success off the presence of `id`; the no-work shape is `{"claimed": false, "retry_after": N, ...}`. This delta is recorded in [`CONTRACTS.md` §6](../../CONTRACTS.md).
